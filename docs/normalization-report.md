**Новые этапы и контракт**

Raw Pretalx → структурное извлечение → semantic rich text → разбор имён/соавторов →
канонизация организаций → объединение авторов с объединением их организаций →
дедупликация организаций и назначение ID → keywords → QA → YAML схемы 2 → renderer.

Registry содержит только явные варианты учреждений. Подразделение с адресом не
приравнивается автоматически ко всему университету: например, подробная кафедра
МГУ в `LRMKSE` сохранена отдельно от общей аффилиации МГУ у соавторов.
Сопоставление по приблизительной похожести имён/организаций отсутствует.

Renderer больше не разбирает соавторов, не исправляет ФИО/keywords, не объединяет
авторов/организации и не диагностирует признаки учреждения в имени. Он использует
готовые имена, ID и семантические узлы; единственная организация отображается без
маркеров. Несколько организаций автора отображаются одним надстрочным списком ID.

HTML `<p>` и пустая строка задают абзацы; `<br>` задаёт перенос строки. Одиночный
перенос в plaintext трактуется как wrapping и превращается в пробел. Поэтому у
источников с одиночными CRLF не создаются дополнительные абзацные отступы.
Поддержаны italic/bold/sup/sub и вложенные узлы. Научные индексы берутся из
исходной разметки (`<sup>`, `<sub>`, `^7`, `_2`, `^{−8}`), а не из догадок по
`107` или `CO2`. В YAML нет готового LaTeX.

Keywords разделяются по `,` и `;`, очищаются от пустых элементов, повторных
пробелов, пробелов перед пунктуацией и завершающей точки. Начальная буква меняется
только у явно перечисленных обычных слов; названия организаций, аббревиатуры,
латинские таксоны и формулы сохраняются.

**QA и оставшиеся замечания**

QA использует одну систему для JSON, TXT, CSV и редакторского Markdown.
Добавлены/перенесены `suspicious_author_affiliation_leak`,
`noncanonical_person_name`, `duplicate_author`, `placeholder_email`,
`missing_abstract`, `missing_keywords`, `suspicious_keyword`, `unparsed_coauthor`,
`duplicate_affiliation`, `suspicious_affiliation_contains_person_name`,
`invalid_affiliation_reference`, `invalid_affiliation_id`, `author_without_name`,
`invalid_richtext`, `references_present_but_no_intext_citations`, `mixed_citation_style`.
Повторяющиеся организации, уже объединённые нормализатором, отмечаются как INFO;
пропуски, необычные имена и placeholder email — WARNING. Отсутствующее имя,
невалидные ссылки ID, невалидный AST и явно невозможный разбор списка — ERROR.
Только ERROR блокирует обычную сборку.

В текущих данных: 92 INFO, 15 WARNING у 9 заявок, 0 ERROR; у «Биоты» нет WARNING/ERROR.

Библиографические диагностики консервативны: распознаются явные ссылки и отдельные

**Проверки**

38 тестов проходят. Они покрывают обязательные примеры задания, inline whitespace,
вложенные richtext-узлы, paragraphs/wrapping, missing values, aliases, несколько
аффилиаций, Unicode/пунктуацию, порядок ФИО, дедупликацию с объединением связей,
leak-маркеры без учёта регистра, неоднозначных/индексированных соавторов,
placeholder email, bibliography diagnostics, schema migration/round trip,
QA severity/build gate, program order, plenary groups, sponsor assets и intentional
заглушки редакторов/составителя. Семь тестов используют реальные выдержки «Биоты».
В исходном checkout отдельного существующего набора тестов не было.
Ruff check, Ruff format check и `git diff --check` проходят.

Дополнительно для всех 122 abstract сопоставлены исходная и нормализованная
последовательности букв/цифр: различий нет. Это проверка потерь содержания,
а не проверка научной корректности или пунктуации. Сохранённый YAML совпадает с
результатом окончательного нормализатора, а сохранённый LaTeX — с окончательным
renderer. Подсчёт секций и пленарных групп записан в `build/regression-check.json`.

Визуально просмотрены все 18 страниц докладов «Биоты»: с. 14 и 52–68, включая
продолжения. Проверены также обложка, выходные данные со спонсорами и намеренными
заглушками, первая/последняя страницы TOC, пример секции 1 и длинного заголовка
секции 4. Переполнений строк и отсутствующих glyph в финальном LaTeX log нет.
В логе остаётся предупреждение о замене недоступного сочетания bold italic для
Libertinus Sans; видимые проблемы на проверенных страницах не обнаружены.

**Выполненные команды**

PowerShell, из корня репозитория; сетевой `all` выполнен повторно после реализации.
Секретный токен в команды/отчёт не передавался. Применялись публичные endpoint.

```powershell
uv sync --cache-dir .uv-cache
uv add 'markdown-it-py>=3,<5' --cache-dir .uv-cache
$env:PRETALX_BASE_URL = 'https://conf.esoil.ru'
$env:PRETALX_EVENT = 'pgb2026'
.\.venv\Scripts\esoil-proceedings.exe all
.\.venv\Scripts\esoil-proceedings.exe normalize
.\.venv\Scripts\esoil-proceedings.exe validate
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\ruff.exe check src tests
.\.venv\Scripts\ruff.exe format --check src tests
git diff --check
.\.venv\Scripts\esoil-proceedings.exe build
.\.venv\Scripts\esoil-proceedings.exe render-preview
pdfinfo build/proceedings.pdf
```

`render-preview` сам повторно собирает PDF и создаёт 29 PNG: стандартные образцы
и все страницы «Биоты». Для очередного запуска достаточно `all`, затем
`render-preview` (либо `build`, если PNG не требуются).
